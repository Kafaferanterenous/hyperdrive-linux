SESSION 20 - 2026-09-22 (inbuilt PDF viewer, Pdfium engine)
------------------------------------------------------------
USER REQUEST: open-source inbuilt PDF preview; fast, low RAM, opens a
window automatically when a .pdf is double-clicked. Delivery must stay a
single portable file (AppImage).
DECISION: Pdfium via pdfium-render 0.9 crate; MIT/Apache bindings keep
HyperDrive GPL-3.0 clean. libpdfium.so (7.8 MB, bblanchon/pdfium-binaries
linux-x64) rides INSIDE the AppImage so the shipped file stays one.
(Rejected: MuPDF crate = lower RAM but AGPL would re-license the whole
binary; pdf-rs = pure Rust but weakest rendering, kept as future option.)
IMPLEMENTATION (src/pdfpreview.rs):
- Engine held in a process OnceLock<Pdfium>; documents get 'static so the
  self-referential 'a on PdfDocument disappears.
- Engine located via PDFIUM_LIB_PATH (file or dir), then exe dir, then
  system lib. load_engine() returns None gracefully.
- Lazy rendering: pages rasterized on demand with a HashMap<i32, Texture>
  LRU capped at MAX_CACHED_PAGES=24; a long doc cannot eat unbounded RAM.
- RENDER_WIDTH=1100 px target; zoom 0.5x..4x re-rasterizes at new width.
- smart_open() routes *.pdf to the viewer (both panes through one choke
  point); egui::Window with ◀/▶ page nav + zoom -/+; closes via ×/Esc.
TEST: renders_first_page_headless generates a 1-page PDF with a correct
xref, opens it through the same GUI code path with a headless
egui::Context, asserts pages==1, texture >10px, and page 99 returns false.
Skips itself when the lib is absent (set PDFIUM_LIB_PATH to exercise).
STATUS: 11/11 cargo tests, 0 clippy warnings, installed to /usr/bin.
LIVE GUI run: window is reachable; live render/zoom/scroll visually
verified to be retried (X11 synthetic-input automation on this box is
flaky - app sometimes dies under rapid xdotool bursts; the headless test
is the reliable proof).
TODO: make-appimage.sh must copy libpdfium.so into the AppImage and (if
shipping installed /usr/bin) place it beside the binary; add WASM/other
platform libs per docs; measure RSS with a page open vs closed.
Caveat: viewer is read-only (no form fill, no editing) by design.

SESSION 17 - 2026-09-16 (search filters actually wired + regression tests)
---------------------------------------------------------------------------
ROOT CAUSE (verified by reading, not trusting notes): app_search.rs had
THREE latent bugs vs the SESSION 12/13 claims:
1) `let needle = q;` inside the thread (was: line 71) overwrote the parsed
   needle with the FULL composite query "needle|ext|kb|flag", so both
   filename AND content matching against `contains(&needle)` could never
   match a real name.
2) ext_filter was parsed as `_extf` and discarded -> the "extension" filter
   did nothing.
3) min_size_kb parsed as `_minkb` and discarded -> the "min-KB" filter did
   nothing.
REIMPLEMENTED: search thread now drives a pure, testable
`file_matches(name, path, needle, extf, minkb, do_content)` helper that
encodes the real contract: dotfiles never match, case-insensitive filename
match, extension filter, min-KB filter, content grep (text-like <1MB, no
NUL byte in first 512B).
TESTS ADDED (app_search.rs): filename match case-insensitivity, dotfile
skip, extension filter restrict, min-size skip, content-grep text-only +
binary skip + huge-file skip. (One test initially failed because "big.txt"
matches needle "x" via the ".txT" extension - renamed to hugefile.data.)
CURRENT: 10/10 tests pass; release rebuilds clean (0 errors). Search
filters (extension + min-KB + content grep) now actually work as claimed.
